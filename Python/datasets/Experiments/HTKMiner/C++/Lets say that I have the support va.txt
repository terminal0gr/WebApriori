CLAUDE RESPONSE:
Yes, store masks. The bigger gain, though, is computing the supports **per itemset**, not per rule.

**Key observation**

For an itemset `I` with `n` items, every non-empty proper subset `S` appears twice: as the antecedent of the rule `S ⇒ I\S`, and as the consequent of the rule `I\S ⇒ S`. So you need only the `2^n - 2` subset supports, stored in a dense array `sup[mask]`. For a rule with antecedent mask `m`:

- `support(X) = sup[m]`
- `support(Y) = sup[full ^ m]`

That is two array reads and no intersection per rule.

**Computing `sup[mask]` cheaply: depth-first over the subsets**

Intersecting from scratch for each subset costs about `n - 2` ANDs each. Instead, extend a subset by one item at a time and reuse the parent's bitset, so each subset costs **one** AND. A stack of at most `n` scratch bitsets is enough, so memory stays small.

```cpp
#include <array>
#include <bit>
#include <cstdint>
#include <vector>

// Fused AND + popcount, stores the result (needed when the subset has children).
inline int andStore(const std::uint64_t* a, const std::uint64_t* b,
                    std::uint64_t* out, std::size_t W) {
    std::size_t c = 0;
    for (std::size_t w = 0; w < W; ++w) {
        const std::uint64_t v = a[w] & b[w];
        out[w] = v;
        c += std::popcount(v);
    }
    return static_cast<int>(c);
}

// Fused AND + popcount, no store (leaf subsets: nothing extends them).
inline int andCount(const std::uint64_t* a, const std::uint64_t* b, std::size_t W) {
    std::size_t c = 0;
    for (std::size_t w = 0; w < W; ++w)
        c += std::popcount(a[w] & b[w]);
    return static_cast<int>(c);
}

// Visits every subset of size >= 2 exactly once; items are added in increasing index.
static void dfs(const std::uint64_t* const* item, std::size_t n, std::size_t W,
                const std::uint64_t* cur, std::uint32_t mask, std::size_t from,
                std::uint64_t* scratch, int* sup)
{
    for (std::size_t k = from; k < n; ++k) {
        const std::uint32_t nm = mask | (std::uint32_t{1} << k);
        if (k + 1 < n) {                                   // may have children: store
            sup[nm] = andStore(cur, item[k], scratch, W);
            dfs(item, n, W, scratch, nm, k + 1, scratch + W, sup);
        } else {                                           // leaf: count only
            sup[nm] = andCount(cur, item[k], W);
        }
    }
}
```

The `scratch` slot at a given depth is reused across loop iterations, which is safe because each child call finishes before the next iteration overwrites it.

**Generation**

```cpp
std::vector<AssociationRule> generateAllRules(
    const std::vector<TopKFIM>& topKFI,
    const std::vector<Candidate>& firstLevelData,
    const std::vector<int>& itemToIdx)          // item id -> index in firstLevelData
{
    if (firstLevelData.empty()) return {};

    std::size_t total = 0, maxN = 0;
    for (const auto& fi : topKFI) {
        const std::size_t n = fi.items.size();
        if (n >= 2 && n <= 31) {
            total += (std::size_t{1} << n) - 2;
            maxN = std::max(maxN, n);
        }
    }

    std::vector<AssociationRule> rules;
    rules.reserve(total);

    const std::size_t W = firstLevelData.front().bits.data.size();
    std::vector<std::uint64_t> scratch(maxN * W);        // reused for every itemset
    std::vector<int> sup(std::size_t{1} << maxN);        // sup[mask], reused as well

    for (std::uint32_t t = 0; t < topKFI.size(); ++t) {
        const auto& items = topKFI[t].items;
        const std::size_t n = items.size();
        if (n < 2 || n > 31) continue;
        const std::uint32_t full = (std::uint32_t{1} << n) - 1;

        std::array<const std::uint64_t*, 32> bits;
        for (std::size_t k = 0; k < n; ++k) {
            const Candidate& c = firstLevelData[itemToIdx[items[k]]];
            bits[k] = c.bits.data.data();
            sup[std::uint32_t{1} << k] = c.support;      // singletons: no intersection
        }
        for (std::size_t k = 0; k < n; ++k)
            dfs(bits.data(), n, W, bits[k], std::uint32_t{1} << k, k + 1,
                scratch.data(), sup.data());

        for (std::uint32_t mask = 1; mask < full; ++mask)
            rules.push_back({t, mask, sup[mask], sup[full ^ mask]});
    }
    return rules;
}
```

**Why this is fast**

- **One AND per subset.** The cost per itemset is about `2^n × W` word operations, where `W` is the number of 64-bit words per bitset. The naive approach costs about `(n-2) × (2^n - 2) × W`, so you save a factor of roughly `n`.
- **Singletons and `sup(I)` are free.** Singleton supports come straight from `firstLevelData`, and you already know `support(I)`, so `confidence = topKFI[t].support / supX` needs nothing extra.
- **Fused AND + popcount.** Your `intersect` followed by `count()` reads and writes memory twice. The fused loops do a single pass, and leaves skip the store entirely. With `-O3 -march=native` the compiler can vectorize the AND and use `popcnt`.
- **No allocations in the hot path.** `scratch` and `sup` are allocated once and reused for every itemset.

**Why masks beat `std::vector<int>`**

- A rule shrinks from two vector headers (48 bytes) plus two heap allocations plus the items, to 16 bytes with no allocations.
- Looking up a subset's support is an array index. With vectors it would need a hash or search over the items.
- The consequent is redundant: `full ^ antecedent`. Store only the antecedent.
- To print or export a rule, convert the mask to items on demand with the `countr_zero` loop.

The limits are that a mask is relative to its parent itemset (hence the `itemset` index in the rule), and that `uint32_t` limits `n` to 31. That is not a practical restriction, since `2^31` rules would not fit in memory anyway. Use `uint64_t` for the mask if you ever need more.

**Two further options**

- **Skip materializing rules.** If you filter by confidence or lift right away, compute the metrics inside the final `mask` loop and keep only the rules that pass. That removes the `2^n - 2` rule records entirely.
- **Hash lookup instead of bitsets.** By downward closure, every subset of a frequent itemset has support at least `support(I)`, so it should itself be among your frequent itemsets. In that case `support(X)` is a hash lookup (about `O(|X|)`) instead of an intersection (`O(W)`), which wins when there are many transactions. The caveat is top-K truncation: a subset with the same support as the K-th itemset can be cut off by the tie-breaker. If that can happen, fall back to the bitset computation for the missing ones.

The per-itemset work is independent, so when you add threads later, each thread only needs its own `scratch` and `sup`.
